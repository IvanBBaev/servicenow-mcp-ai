## [Unreleased]

### Breaking changes

These are the 3.0 changes the owner approved on 2026-10-01 (O-4). Each write-safety default has an explicit opt-out.

- **B3: error contract v2 (M-2).** A failed tool result is now one flat JSON object: `{ error, code, source, status?, hint?, detail? }`.
  - `error` is the message (it was `error.message`). `code` is always present: a code from the table in `src/core/errors.ts` (`NOT_CONFIGURED`, `POLICY_DENIED`, `PLAN_REQUIRED`, `PLAN_EXPIRED`, `UNREADABLE`, `INSTANCE_HTML_RESPONSE`, `RECIPIENT_NOT_ALLOWED`, `CREDENTIALS_INCOMPLETE`, `CANCELLED`, `INVALID_INPUT`, `NOT_FOUND`, `INTERNAL_ERROR`, …) or `INSTANCE_HTTP_<status>` for a non-2xx instance answer that no more specific code covers.
  - `source` is new: `servicenow` (the instance answered with an error), `policy` (this server's policy or a confirmation step refused the call) or `server` (validation, transport, configuration, bugs).
  - `snDetail` is renamed `detail` (the instance's own error object). `hint` is the fix in one sentence. Policy denials now name the setting to change (`SN_TABLES_DENY`, `SN_TABLES_ALLOW`, `SN_PROTECTED_TABLES_WRITE`, `SN_READONLY`, `SN_IMPORT_SET_TABLES`, `SN_PACKAGES_DENY`, `SN_PACKAGES_READONLY`), and `doctor` reports a `hint` per failed check (`Fix:` in the text report).
  - A plan token whose TTL elapsed is now `PLAN_EXPIRED` (it was `PLAN_REQUIRED`). A 401 under Basic auth is `INSTANCE_HTTP_401` (token mode keeps `AUTH_EXPIRED`).
  - Messages no longer repeat the code as a prefix: `CREDENTIALS_INCOMPLETE: …` and the M-5 `UNKNOWN_PACKAGE: …` / `PACKAGE_DENIED: …` / `PACKAGE_ALWAYS_ON: …` messages now carry the code in `code` only; hints moved from the message into `hint`.
  - Resource reads (`servicenow://…`) throw an MCP `McpError` instead of returning a 200 body with an `error` field: a malformed URI, an unknown profile or a missing document is `InvalidParams` (-32602; the SDK has no ResourceNotFound), anything else `InternalError` (-32603). The error's `data` carries `{ code, source, hint? }`. The docs resource template no longer declares a fixed `text/markdown` type, since it also serves JSON companions; each listed entry and each read declares its own.
  - The tool manifest is now `manifestVersion: 3` and publishes the code table as a global `errorCodes` object (code → `{ source, description }`, including the `INSTANCE_HTTP_<status>` family). The table is global rather than per tool because most codes come from shared layers (HTTP, policy, configuration), so a per-tool list would over-promise.
  - Internals (ARCH-11b): `IntegrationError` is the neutral base class; `ServiceNowError` and `JiraError` are siblings under it, so `JiraError` is no longer a `ServiceNowError`.
  - **Migration:** read `result.error` as the message, not `result.error.message`; read `code`, `source`, `hint` and `detail` from the top level; replace `snDetail` with `detail`; branch on `code`, not on message text. Resource clients catch the JSON-RPC error and read `error.data.code`. Manifest consumers accept version 3.

- **B4: a destructive `apply:true` needs a `plan_token` (H-3).** `SN_DESTRUCTIVE_CONFIRM` now defaults to `token` (it was `off`). In plan mode (the default), the following calls are refused with `PLAN_REQUIRED` (428) before any request unless they carry the `plan_token` from their own plan preview:
  - `servicenow_delete_record` and `servicenow_delete_attachment`;
  - `servicenow_batch` with a write sub-request;
  - `servicenow_send_email` and `servicenow_order_catalog_item`;
  - `servicenow_revert_write` and `servicenow_upsert_artifact`;
  - `servicenow_check_change_conflicts` (2.x: `servicenow_change_conflicts`) with `calculate:true`.

  A token can be used once and expires after `SN_PLAN_TOKEN_TTL_SEC` (600 s by default). `SN_WRITE_MODE=apply` still skips the token, except on a prod profile.
  - **Migration:** call the tool without `apply` first, then repeat the same call with `apply:true` and the `plan_token` from that preview. To restore the 2.x behaviour, set `SN_DESTRUCTIVE_CONFIRM=off`, or set `SN_WRITE_MODE=apply` for trusted automation.

- **B8: `batch` denies unmapped `/api/*` paths and caps the request count (H-4).**
  - `SN_BATCH_UNMAPPED` now defaults to `deny`. A sub-request whose REST prefix maps to no package is refused with `POLICY_DENIED`.
  - `SN_BATCH_MAX_REQUESTS` now defaults to 50 (it was 1000). The cap is checked before any request is built.
  - **Migration:** set `SN_BATCH_UNMAPPED=allow` to forward unmapped paths. Raise `SN_BATCH_MAX_REQUESTS` (up to 1000) or split large batches.
- **B11: protected system tables are write-denied by default (H-11).**
  - `SN_PROTECTED_TABLES_WRITE` now defaults to `deny`. Creates, updates, deletes, upserts, reverts, import-set inserts, CMDB writes and batch writes on these tables return `POLICY_DENIED`: `sys_user`, `sys_user_has_role`, `sys_user_role`, `sys_user_grmember`, `sys_security_acl`, `sys_security_acl_role`, `sys_properties`, `oauth_entity`, `sys_auth_profile_basic`, `sys_script`, `sys_ws_operation`, `sys_public`, `sys_ldap*`, `sys_certificate`, `sys_data_source` and `sys_rest_message*`.
  - This means `servicenow_set_property` and business-rule writes are refused by default. Reads are not affected.
  - **Migration:** to open one table, add it as an exact entry in `SN_TABLES_ALLOW`. To restore the 2.x behaviour, set `SN_PROTECTED_TABLES_WRITE=allow`.
- **Import sets accept staging tables named `u_*` and `imp_*` by default (H-11).** `SN_IMPORT_SET_TABLES` used to be unrestricted and now defaults to `u_*,imp_*`. Scoped staging tables such as `x_acme_stage` are refused until you list them.
  - **Migration:** add the table's pattern to `SN_IMPORT_SET_TABLES`, or set it to `*`.
- **Write caps are on by default (H-11).** `SN_MAX_DELETES_PER_SESSION` defaults to 100 and `SN_MAX_BATCH_WRITES` to 50. `SN_MAX_WRITES_PER_SESSION` defaults to 500 for each HTTP session; stdio sessions stay uncapped. A call over a cap is refused with `WRITE_CAP` (429) and journaled.
  - **Migration:** set the variable to a higher number, or to `0` for no cap. A single batch is limited by `SN_BATCH_MAX_REQUESTS` (50) before it can reach the 50-write cap.

- **B2: tool naming convention v3 (M-7).** Every tool is now `servicenow_<verb>_<noun>`; `servicenow_aggregate`, `servicenow_batch`, `servicenow_where_used` and `servicenow_identify_reconcile` keep their names. Eleven tools are renamed (table below). The tool manifest is now `manifestVersion: 4`: it publishes the renames as `toolRenames`, and per tool the accepted parameter aliases (`legacyParams`, `deprecatedParams`) and the reason a tool overlaps another (`overlap`: `get_status` / `test_connection` / `check_capabilities`, `list_atf_tests` / `list_atf_suites`, all kept).

- Parameters are normalised. Record ids are `sys_id`: `attachment_sys_id` (get / download / delete attachment), `item_sys_id` (get / order catalog item), `catalog_sys_id` (list catalog categories), `test_sys_id` (run ATF test) and `suite_sys_id` (run ATF suite) are renamed. The table is `table`: `staging_table` (import set tools) and `class_name` (CMDB tools) are renamed. `fields` now always means the list of columns to return; a write payload is `values`: `fields` on `create_record`, `update_record`, `upsert_record`, `create_change`, `update_change`, `insert_import_set_row` and `upsert_artifact` (top level and `children[]`), and `attributes` on `create_ci` / `update_ci`, are renamed. `run_atf_*` keep `execution_id` (a CI/CD progress id, not a record).
- `class_name` stays accepted on the CMDB tools as a documented deprecated alias of `table`. Passing both an alias and its new name is refused with `INVALID_INPUT`.
- **`SN_LEGACY_TOOL_NAMES=1`** (default off) keeps 2.x clients working for one minor release: the old tool names are registered as aliases that run the new tool (listed in `tools/list` with a deprecated title, one warning per name), and the old parameter names are accepted (one warning per tool and parameter). Without it, old names are unknown tools and old parameters fail validation.
- **Migration:** rename the tools and parameters in your prompts, scripts and client allow-lists using the table above, or set `SN_LEGACY_TOOL_NAMES=1` while you migrate. Manifest consumers accept version 4.
- **B13: per-profile resources move under `servicenow://profiles/` (M-7).**
  - The per-profile schema template is now `servicenow://profiles/{profile}/schema/{table}`. The old `servicenow://{profile}/schema/{table}` still reads the same schema until the next minor release, logs a deprecation warning once and is no longer listed.
  - Profile names `docs`, `schema`, `status`, `capabilities`, `reference`, `profiles` and `policy` are reserved: creating one, or loading an env file that defines one, fails with `RESERVED_PROFILE_NAME` and a hint.
  - **Migration:** read `servicenow://profiles/<profile>/schema/<table>`; rename a profile that uses a reserved name (its `SN_<NAME>_*` variables).

### Added

- **Token measurement harness (N-57).** `test/surface.js` measures the published `tools/list` per profile; a ratchet test fails when a budget sits more than 2 % above its measurement, and `test/tool-size.test.js` caps every tool (total, description, input and output schema) with a reasoned allow-list for the five outliers. `npm run tokens:budget` checks or lowers the budgets; `npm run tokens:report` prints the byte breakdown, estimated tokens, repeated parameter text and the heaviest tools (`--json` for machines).

- **OpenTelemetry MCP spans (N-55).** Tool calls now publish on `node:diagnostics_channel` (`servicenow-mcp:mcp.tool.call.start` / `.end` / `.error`: tool, package, profile, outcome, error code, duration, result size; never arguments or results). The W3C `traceparent` / `tracestate` from `params._meta` are validated and carried into the HTTP channel messages together with the call's `callId`.
  - `SN_OTEL=1` turns the channels into OpenTelemetry spans (a `SERVER` span per tool call, a `CLIENT` span per ServiceNow request) through `@opentelemetry/api`, a new optional peer dependency loaded only when the setting is on. When the package is missing, one warning is logged and nothing else changes. The MCP / GenAI semantic-convention names are provisional.
  - `SN_OTEL_PROPAGATE=1` (off by default) sends `traceparent` / `tracestate` to the ServiceNow instance.
  - With both settings off, the only cost is a `hasSubscribers` check per call; no tool definition or `tools/list` byte changes.
- **Claude Code plugin: two read-only subagents (N-47).** `sn-investigator` answers a question about the instance and returns a short report with its evidence. `sn-change-reviewer` reviews a plan preview or an update set before it is applied and returns a go / hold verdict. Each has an explicit `tools` allowlist made only of this server's read-only tools; `test/plugin-agents.test.js` checks every entry against the manifest's `readOnlyHint`.
- **Claude Code plugin: hooks v2 (N-48).** Two plain Node hooks with no dependencies.
  - A `SessionStart` hook adds the active profile, its instance host, the write mode (plan, apply, read-only or a held prod profile), the tool packages and the other profile names. It reads only the environment and the local env file, makes no network call, never prints a user name, password or token, and is silent on any error.
  - A `PostToolUse` hook adds a one-line hint when a ServiceNow result says `truncated: true`, naming the knobs that tool really has (`fields`, `offset`, `format: "file"`). The knob lists are pinned to the tool manifest.
- **Portable skills (N-52).** The five plugin skills are now checked against the open Agent Skills spec: name format, allowed frontmatter keys, and no client-specific `mcp__` tool names. The README documents installing them for VS Code Copilot, OpenAI Codex and Cursor (`.agents/skills/` works in all three).

- **MCP bundle (`.mcpb`) for one-click installs (N-51, TK-27).** `npm run mcpb:pack` builds `dist/mcpb/servicenow-mcp-ai-<version>.mcpb`, a zip of the compiled server, its production dependencies, `manifest.json` and the icon. Claude Desktop and other MCPB hosts install it in one click and need no `npm` / `npx`. The bundle is built outside the npm package, so the tarball and `pack:check` do not change.
  - `mcpb/manifest.json` (MCPB manifest 0.3) is generated by `scripts/mcpb-manifest.mjs` (`npm run mcpb:manifest`, `--check` runs in `npm run check`):
    - name, version, description, author, license and links come from `package.json`;
    - the tool list comes from the registry;
    - the install form (`user_config`) comes from the settings manifest: every connection / auth key plus the MCP-registry keys (`SN_TOOL_PACKAGES`).
  - Secrets are `sensitive: true`, and only `SN_INSTANCE` is required. No field carries a default, so an empty field falls back to the env file and then to the server default.
  - `loadEnv()` drops an unsubstituted `${user_config.<key>}` placeholder that a host passes for an empty optional field.
  - `mcpb/manifest.json` is a version follower of `scripts/sync-version.mjs`. `npm run mcpb:pack -- --validate` also runs the official `@anthropic-ai/mcpb` validator through `npx`; it is pinned but not a dependency.
  - `test/mcpb-manifest.test.js` covers the mapping, sensitive flags, drift, the zip writer, the placeholder guard and the dormant release job.
- **MCP Apps views, opt-in (N-50).** `SN_MCP_APPS=1` (default off) implements the MCP Apps extension (`io.modelcontextprotocol/ui`, SEP-1865, spec 2026-01-26).
  - Four `ui://servicenow-mcp/…` resources (`text/html;profile=mcp-app`): `plan-diff` (the plan of every write tool with `apply`: per-field before/after and the plan token), `mermaid` (the five Mermaid generators: entities, edge list, source), `flow` (`servicenow_explain_flow`: trigger, nested steps, activities, lanes) and `uib-tree` (`servicenow_explain_ui_experience`: routes → screens → macroponent tree, data brokers).
  - The linked tools carry `_meta.ui.resourceUri`, but only for a client whose `initialize` declares the extension with that MIME type. Tool results never change.
  - Each view is a static, self-contained HTML document (no network, inline script and style, its own CSP with `default-src 'none'` and the script and style pinned by hash, no eval) that renders the tool result the host pushes over `ui/notifications/tool-result`. All record data is HTML-escaped into text nodes. Mermaid is shown as tables and source, not drawn.
  - Off: `tools/list`, resources and every result are byte-identical to before (`test/mcp-apps.test.js`).

- **`ops` v2: integrations, transactions and MID servers (N-6).** `servicenow_read_ops` gains three `kind` values; no new tool.
  - `integrations` reads failed (status >= 400) and slow (over 5,000 ms) outbound calls from `sys_outbound_http_log` and groups them by host and REST message, with status counts, the slowest call and up to three sample URLs. URLs keep only origin and path (no credentials, query string or fragment), as under H-6. An empty log carries a `note`: outbound logging may be off, so it is not proof of health.
  - `transactions` reads slow transactions from `syslog_transaction`, slowest first, grouped by URL with the query string stripped (count, average and maximum response time, distinct users).
  - `mid` reads `ecc_agent` (status counts, name, version, last refresh, host) and, as a sub-section that degrades on its own, the `ecc_queue` backlog (`state=ready` by agent, the oldest ready entry) and the recent `error` rows by agent.
  - All three join `overview` as Aggregate API counts. Each section degrades on its own to `available: false` with the reason, and rows stay capped by `limit`.
  - The filter fields are checked against the dictionary before any count. If a field is missing, the section fails rather than counting every row; if the dictionary is unreadable, the result lists `unverified_fields`.
  - The `servicenow_why_is_it_slow` prompt now reads the `transactions`, `integrations` and `mid` kinds.
  - The table, field and state names are not yet checked on a live instance (O-5).

- **Fluent round-trip oracle (P-29, O-7).** `@servicenow/sdk` 4.12.2 is now an exact dev dependency (never a runtime one). `npm run fluent:verify` (`scripts/fluent-verify.mjs`) does two things with every golden in `test/fixtures/fluent/`. It type-checks the golden against the SDK types with strict `tsc` and excess-property checks. It then runs `now-sdk build` offline, in conflict-free projects, and checks that every declared key comes out under its source sys_id, either as its own update XML or nested in its parent's (flow logic, playbook lanes). It also checks that no `DELETE` record is emitted. `test/fluent-sdk-oracle.test.js` runs the oracle and is skipped when the SDK is not installed (`npm ci --omit=dev`).
  - `npm run fluent:actions` (`scripts/gen-fluent-actions.mjs`) generates `src/api/fluent-sdk-actions.ts`, the `action.core` / `actionStep` input table, from the SDK's built-in definitions.
  - `npm run check` runs `fluent:actions -- --check`, which fails when the table is stale after an SDK bump.
  - All 27 goldens type-check with 0 errors and build: 93 keyed records found among 100 built.
  - Limit: the oracle does not compare field values with live instance records. That needs O-2 / O-5 fixtures.

- **Plugin hook that blocks a token-less destructive apply (D-8).** The Claude Code plugin now ships `hooks/hooks.json`, which runs `hooks/require-plan-token.mjs` as a `PreToolUse` hook on the server's tools. When one of the B4 destructive calls has `apply:true` and no `plan_token`, the hook denies it before the call reaches the server and tells the assistant to preview first.
  - It only checks that a token is present; the server validates it.
  - Input it cannot parse passes through.
  - `SN_DESTRUCTIVE_CONFIRM=off` turns the hook off.
  - The hook ships with the plugin and is not in the npm tarball.
  - `test/plugin-hook.test.js` keeps the hook's tool list identical to the manifest's `plan_token` tools.
- **AST-based lint and a code-health baseline (S-12).** Script lint now parses with `acorn` (new runtime dependency, ~568 KB unpacked, no dependencies of its own; `src/api/script-ast.ts`): ES5 for global-scope records (`sys_scope` = `global`), ES2021 for scoped apps and client fields, with `return` allowed at the top level. The line rules (`hardcoded-sys-id`, `hardcoded-instance-url`, `eval-usage`, `gs-sleep`, `gs-log-deprecated`, `set-workflow-false`, `current-update-in-br`, `sync-get-reference`, `sce-trust-as-html`, `sanitize-bypass`, `gr-on-client`), `query-in-loop` (only inside a loop body), `gr-unbounded-query` (per receiver and function) and `sp-param-unvalidated` run on the syntax tree, so comments and string contents no longer produce findings; the ACL rules `eval-in-acl` / `gr-write-in-acl` / `getuser-in-acl` and the P-19 `portal-public-data-widget` data-read check do the same. Rule ids and finding shapes are unchanged. A source that does not parse (or Jelly `${…}` markup, or one over 512,000 chars) falls back to the regex engine, which reports `syntax-error` as before; the parser never throws to the tool. Additive: per-field `engine` (`ast` | `regex`), `ecma` and `parseError` on script lint results, and the new rule `es2021-syntax-in-es5` (warn — a global-scope script that only parses as ES2021). `servicenow_code_health` keeps a baseline in `<profile>/code-health.baseline.json` (docs store, one scope per `instance` / `table:<t>`): the first run records it, later runs return a `delta` (new / fixed / unchanged / partial per section: lint, artefacts, security, domains) and a "Baseline delta" report section; the new input `update_baseline: true` resets it to the run. Fingerprints leave out line numbers; a finding missing from a capped, unreadable, truncated or unavailable unit is counted `partial`, never `fixed`. `TOOLS_LIST_BUDGET_ALL` unchanged. Tests: `test/s12-ast-lint.test.js` (17 tests, including a fast-check property that the parser never throws through); code-health writer goldens updated.

No new tool or setting.

- **More Table API parameters (S-8).** `servicenow_query_table` takes `view`, `queryCategory`, `noCount`, `queryNoDomain` and `suppressPaginationHeader` (`sysparm_view`, `sysparm_query_category`, `sysparm_no_count`, `sysparm_query_no_domain`, `sysparm_suppress_pagination_header`); `servicenow_create_record`, `servicenow_update_record` and `servicenow_upsert_record` take `inputDisplayValue` (`sysparm_input_display_value`).
- **Encoded-query reference (S-8).** New resource `servicenow://reference/encoded-query` (table package) documents the encoded-query syntax and its limits — no escaping of `^`, URL length (HTTP 414), unknown fields silently ignored, ACL-hidden rows — and how `fetchAll` pages; the `servicenow_query_table` description summarises the limits.
- **Capability matrix (S-13).** `servicenow_check_capabilities` (and the `servicenow://capabilities` resource) now also returns a `matrix` with one read-only, policy-routed probe per group — `writes` (derived from `SN_READONLY` / `SN_WRITE_MODE` / `SN_PACKAGES_READONLY`, no request), `update_sets` (the user's current update set), `attachments`, `aggregate`, `import_sets`, `email`, `atf`, `version` (`glide.buildtag` and the release family) and `roles` (admin flag and notable roles). Each group reads `available`, `unavailable` (401/403/404), `plan-only`, `read-only` or `unknown` (a table or package denied by policy is not probed, a 5xx, a transport error, ACL-hidden rows). New optional inputs `groups` (narrow the matrix) and `refresh` (drop cached results). Results are cached per instance and user — successes for `SN_CAPABILITY_TTL_MS` (default 10 min), failures for `SN_PLUGIN_NEGATIVE_TTL_MS` (default 60 s); transport errors are never cached, and switching credentials or profile clears the cache. `servicenow-mcp-ai doctor` prints the matrix under Capabilities; it does not change the verdict or exit code.
- **Credentials model completeness (D-2).** `hasCredentials`, `doctor`, `servicenow_get_status` and `servicenow_list_instances` evaluate each profile against its own auth method (Basic, API key, bearer token, OAuth per grant, cert-only `none`) — an API-key or bearer profile no longer reports "not configured" for a missing password — and name what is `missing`. `servicenow_set_credentials` takes `auth`, `oauth_client_id`, `oauth_grant` and `request_secrets`: the API key and OAuth client secret are asked for through an elicitation prompt only, never accepted as tool arguments (refused on clients without elicitation), and never echoed, logged or journaled (the journal keeps key names). The H-2 instance-change rule now requires the material of the resulting auth method. A rotated OAuth refresh token is persisted to the env key it came from, kept in memory with a warning when the env file is read-only (L6-01). New `SN_TOKEN_FILE` (bearer token from a file, re-read once on a 401; otherwise the call fails with the new error code `AUTH_EXPIRED` and a hint) and `SN_TOKEN_EXPIRES_AT` (warning when under 24 h remain) (L6-02). `servicenow_get_status` gains `authWarnings`; each `servicenow_list_instances` profile reports `auth`, `grant`, `refreshToken` (`configured` / `rotated-in-memory` / `none`), `writeMode` and `missing`, never a secret (L8-01). The env writer single-quotes values with backslashes (Windows paths stay literal), keeps a CRLF file CRLF, refuses values with line breaks, and warns on Windows to restrict the env file's ACL with `icacls` (never run by the server) (L2-11).

A test walks every tool schema and fails on a new unbounded string or array.
- **Tool annotations (M-8).** Every tool declares all four hints (`readOnlyHint`, `destructiveHint`, `idempotentHint`, `openWorldHint`); the tool definition type now requires them. `servicenow_docs_write` is marked `destructiveHint: true` (it can overwrite a file) and `servicenow_docs_list` / `_read` / `_search` declare `openWorldHint: false`.
- **Strict input schema without a cast (M-8).** `buildInputSchema(spec)` builds the strict object schema (with the automatic `instance` parameter) that `registry.ts` registers, replacing the `.strict()` cast.
- **Plugin-availability cache (S-13).** A plugin API found missing (namespace 404) is now remembered for `SN_PLUGIN_NEGATIVE_TTL_MS` (default 60 s, was a fixed 5 min), and a plugin API seen available expires back to `unknown` after `SN_CAPABILITY_TTL_MS` (default 10 min). `servicenow_check_capabilities` with `refresh: true` clears both.
- **Policy-routed table preflight (S-13).** The `sys_*` table preflight in `servicenow_check_capabilities` no longer sends a request for a table denied by `SN_TABLES_ALLOW` / `SN_TABLES_DENY`; the probe reports `policyDenied: true` with the reason.
- **HTTP retry policy tightened.** `502`/`503`/`504` responses are now retried only for idempotent requests (a write may already have executed on the instance), and a server-supplied `Retry-After` is honoured but capped (`SN_RETRY_AFTER_MAX_MS`, default 60 s) so a misbehaving proxy cannot stall a call indefinitely.
- **Process lifecycle.** An unhandled promise rejection now ends the process the way an uncaught exception does: one structured, secret-free error line (pid, uptime, transport, error name and message — never a stack) is written, stderr is flushed and the server exits 1, instead of logging and running on with possibly corrupt state. SIGTERM behaves like SIGINT (graceful close, exit 0). On shutdown and whenever an HTTP session closes, the in-process singletons (schema cache, cached OAuth tokens, the per-host request queue and circuit breakers, the cached proxy / TLS dispatchers, HTTP telemetry, plugin availability) are reset through one `dispose()`, and the HTTP transport fails startup when its port cannot be bound instead of raising a stray error event.
- **Runtime container (internal).** The process state that used to live in module singletons — schema cache, cached OAuth tokens, per-host request queue and circuit breakers, proxy / TLS dispatchers, HTTP telemetry, the credential profile store and plugin availability — now lives in one runtime object built once at start-up (`createRuntime()` in `src/core/runtime.ts`) and handed to `registerAllTools`, which binds every tool call to it. `dispose()` clears it in place and is idempotent; the test-only `_reset*` hooks are gone (tests build their own runtime). No behaviour or `servicenow_get_status` shape change.
- **Artefact registry (internal).** A single typed registry (`src/core/artifacts/registry.ts`, SDK baseline 4.12.2) now describes each ServiceNow artefact type: table, child tables, name and key fields, script and JSON fields, references, SDK API and tiers. The script-tool type map and the capability probe list are derived from it with identical output, so no tool behaviour changes. Unverified descriptors are seeded for portal, UI page, UI Builder, flow, workflow, catalog, scripted REST, fix-script, email-script and transform-map artefacts, and are kept out of the script tools for now.
- **One request budget instead of per-attempt timeouts alone.** A logical request now stops at `SN_DEADLINE_MS` with `DEADLINE_EXCEEDED` even when every attempt fits in `SN_TIMEOUT_MS`; a retry that cannot fit in the remaining budget fails fast instead of waiting it out, and a caller-supplied abort is honoured and never retried.
- **Bounded per-host queue.** Requests beyond `SN_MAX_CONCURRENT` wait at most `SN_QUEUE_TIMEOUT_MS`, and at most `SN_MAX_QUEUE` wait at once — overflow fails fast with `BUSY` instead of piling up; `servicenow_get_status` and the `doctor` diagnostics bypass the queue so they still answer while the instance is saturated.
- **Upstream error pages are shaped.** A non-JSON error body (a proxy or login page, a hibernating instance) is classified `UPSTREAM_HTML`, tag-stripped and capped at 512 characters with a hint; JSON error detail is capped at 2 KB — a 300 KB HTML 502 no longer lands in the tool result.
- **OAuth requests share the HTTP client.** Token and code-exchange requests use the same primitive as API calls (dispatcher, `User-Agent`, deadline, the `auth` telemetry bucket, retry only for replayable requests) — under a proxy or mTLS they no longer bypass the configured transport.
- **`fetchAll` pages by `sys_id` cursor (S-8, C-2).** Without an `ORDERBY`/`ORDERBYDESC` (and without `^NQ`), a `fetchAll` read orders by `sys_id` and fetches each next page with `sys_id>last` instead of an offset, so rows inserted or deleted during the read no longer shift pages (skipped or duplicated rows). `sys_id` is requested for the cursor and stripped again when `fields` did not ask for it; a caller ordering keeps offset paging. `filtered` is exact when `X-Total-Count` is present and not reported otherwise in cursor mode.
- **`.env.example` is generated (D-3).** The file is regenerated from the settings manifest (every key, grouped by section, with defaults), and it now recommends `~/.config/servicenow-mcp-ai/.env` instead of the stale `sincronia-mcp` path. The `server.json` `environmentVariables` block is generated from the same source; its content is unchanged.

### Security

- **Type-based secret masking, always on (N-21).** Behaviour change: a column whose dictionary `internal_type` is `password`, `password2` or `glide_encrypted` is now masked as `[redacted]` in every tool result and in the write journal (`fields`, `before`, `error`), whatever `SN_REDACT_FIELDS` says, and no setting turns it off.
  - Every Table API read and write, direct or inside `servicenow_batch`, resolves its secret columns from one cached `sys_dictionary` query per profile and, only when a key matches a secret column name, the table's inheritance chain (`sys_db_object`). Both are schema-cached (`SN_SCHEMA_CACHE_TTL_SEC`). Dot-walked keys are matched on their leaf name, and `{ value, display_value }` pairs are masked whole.
  - The secret values a call read are also masked wherever the same call re-embeds them, so `servicenow_compare_instances` diffs, documents and exports cannot carry one under another key. A password-type system property's `value` is masked the same way.
  - A schema miss (an ACL-restricted dictionary, a denied table, an error) never blocks the read: a list of OOTB secret column names (`password`, `user_password`, `client_secret`, `api_key`, `private_key`, …) applies, and it applies always as a floor. This means a field named `password` is now masked even with redaction off, including in `servicenow_set_credentials` results that already showed `***` (they keep `***`).
  - Limits: other REST surfaces (CMDB, import set, plugin APIs) are masked by the OOTB names only; values shorter than four characters are masked by their key only, not where re-embedded.
- **Deep redaction at the result boundary.** `SN_REDACT_FIELDS` / `SN_REDACT_PII` now apply to every tool result — success and error, nested objects included, write tools' echoed records too — and to the `fields`, `before` and `error` values in the write journal, instead of only the top-level fields of query results.
- **Docs store hardened.** Writes through the docs store reject the journal's own files (`write-journal.*`) and any path that leaves the docs directory through a symlink (the nearest existing ancestor is resolved and must stay inside the real docs root). The `.env` writer uses a unique temp file per write (pid + random suffix) and removes it on failure, so concurrent `servicenow_set_credentials` calls never share a temp file and always leave a complete `.env`, and a failed write leaves no plaintext copy behind.
- **Credential host binding.** `servicenow_set_credentials` now refuses to move a configured profile to a different instance unless `user` and `password` arrive in the same call (`CREDENTIALS_INCOMPLETE`; nothing is written and no cache is touched), so the secrets stored for one host can never be sent to another. The elicitation confirmation also fails **closed**: a client that cannot confirm the change (no elicitation capability, no live server, or a prompt error) is refused unless the operator sets `SN_ALLOW_UNCONFIRMED_CREDENTIAL_CHANGE=1`; an explicit decline is always refused.
- **Dependency floors raised; the production audit is clean again.** `@modelcontextprotocol/sdk` now requires `^1.30.0` (installed 1.30.0) and `zod` `^3.25.0` (the SDK's peer range). The lock picks up the patched transitive `fast-uri`, `ip-address`, `hono`, `@hono/node-server`, `qs` and `body-parser`, so `npm audit --omit=dev --audit-level=high` — the last step of `npm run check` — exits 0 again, with no `overrides`.
- **Explicit ports and IPv6 literals need an allow-list entry.** An instance value with a non-443 port or a bracketed IPv6 address (`host:8443`, `[2001:db8::1]`) is accepted only when `SN_ALLOWED_HOSTS` names it, so a crafted host cannot steer credentials to an unexpected service. Proxy credentials in `SN_HTTPS_PROXY` / `HTTPS_PROXY` are never logged or returned, and `SN_TLS_REJECT_UNAUTHORIZED=false` logs a warning the first time a connection is built.
- **Outbound hardening (H-6).** HTTP redirects are never followed: a 3xx fails with `REDIRECT_BLOCKED` naming the target host, so a body or auth header cannot be forwarded to another origin (API, Jira and OAuth token requests alike). An `SN_ALLOWED_HOSTS` suffix entry no longer opens an internal or loopback host — only an exact entry does — and the internal-range check now covers IPv6 (loopback, unspecified, link-local, unique-local, IPv4-mapped and -compatible forms). `send_email` recipients (to, cc, bcc) must be single addresses (at most 50 per list) inside `SN_EMAIL_ALLOWED_DOMAINS`, or — **new default** — users in the instance's own `sys_user` directory; a failed directory lookup fails closed (`RECIPIENT_NOT_ALLOWED`). The OAuth loopback listener answers stray paths (404) and foreign `state` (400) without aborting the login. Upload file names are reduced to a sanitised leaf name (no path, control or bidi characters, 255 bytes). The docs store rejects Windows device names and `:` streams and refuses paths that leave the folder through a symbolic link. `SN_TLS_REJECT_UNAUTHORIZED=false` now also warns at startup and in `servicenow_get_status` (`http.warnings`).

## [2.0.0] - 2026-06-22

v2.0 makes the breadth of v1 **safe and self-aware**: writes preview before they run, the server reports which capabilities it can actually achieve on your instance, and `code_health` audits the access-control layer. (v1 = breadth; v2 = trust + depth.)

### Breaking changes

- **Writes are plan-by-default.** `SN_WRITE_MODE=plan` is the new default. The write tools — record CRUD (`create`/`update`/`delete_record`), change (`create`/`update_change`), CMDB CI (`create`/`update_ci`), import-set insert, **email send**, **catalog order**, **attachment upload/delete**, **batch** (when it contains writes), and the **ATF run** tools — now return a non-mutating **before/after preview** instead of executing.
  - **Migration:** to apply a change, pass `apply: true` on the call, or set **`SN_WRITE_MODE=apply`** to restore the v1.x "execute immediately" behaviour globally. Automations that relied on a write running on the first call must do one of these.

### Added

- **DF-0 — capability preflight.** New always-on `servicenow_check_capabilities` tool and `servicenow://capabilities` resource: probe which admin-restricted `sys_*` tables the connected user can actually read, and report which capabilities (schema reads, script intelligence, ACL audit) are achievable — so the script/codecheck tools never promise a read they cannot make. `servicenow_table_logic` now degrades a 401/403 on one artefact type to an `unreadable` flag instead of failing the whole overview. (67 tools / 18 packages.)
- **DF-2 — plan-and-apply + local audit journal.** `SN_WRITE_MODE` (plan|apply) and a per-call `apply` argument gate every record-style write tool; each applied mutation is appended to a per-profile, append-only journal at `<SN_DOCS_DIR>/<profile>/write-journal.{jsonl,md}` — a client-side audit trail where there is no AI Control Tower.
- **DF-1 — ACL security scan.** `servicenow_code_health` now folds in a security dimension over the active ACLs (`sys_security_acl`): `eval`/side-effects/`gs.getUser` in ACL evaluation scripts, and roles-only ACLs (no condition and no script). The `sys_security_acl` read is gated behind DF-0 — when it is unreadable the scan reports the role needed rather than a silently empty all-clear.
- **DF-4 — where-used / impact graph.** New `servicenow_where_used` tool: find where a table, field or script is referenced across the instance's code — textual references in every script source, plus (for a table) the business rules, client scripts, UI policies/actions and ACLs attached to it. Read-only; optional Mermaid reference graph. The IDE-grade "find usages" the platform lacks.
- **DF-5 — client-side field redaction.** `SN_REDACT_FIELDS` masks named field values before query results are serialised for the model; `SN_REDACT_PII` also masks email/phone/national-id patterns inside any string value. Opt-in (off by default); the redaction count is reported in the result.
- **DF-6 — HTTP transport.** `SN_TRANSPORT=http` (port `SN_PORT`, default 3000) serves the MCP server over **Streamable HTTP** so the official ServiceNow MCP Client app and remote clients can consume it; the default stays `stdio`. The endpoint binds to **loopback (`127.0.0.1`) by default** (`SN_HTTP_HOST` to widen) and supports an optional **`SN_HTTP_TOKEN`** bearer guard (constant-time check); broader TLS/network hardening remains the operator's responsibility.
- **CSV export.** `servicenow_query_table` accepts `format: "csv"` for a spreadsheet-friendly export — a dependency-free RFC-4180 formatter that reuses the DF-5 redaction.
- **Claude Code plugin (DX-1).** A `.claude-plugin/` bundle (plugin + marketplace manifest) makes the server installable with `/plugin marketplace add IvanBBaev/servicenow-mcp-ai` then `/plugin install servicenow-mcp-ai` — zero-config, the server wired up.
- **DF-3 — CI drift gate.** `servicenow-mcp-ai drift <profileA> <profileB>` promotes `compare_instances` to a release artifact: it prints the Markdown drift report and exits non-zero when the instances differ, so a pipeline can block a deploy on configuration drift.
- **VS Code extension.** An `extension/` sub-package registers the MCP server with VS Code Copilot Chat (agent mode) on install (via `registerMcpServerDefinitionProvider` → `npx -y servicenow-mcp-ai`), so VS Code users get the tools with no manual `mcp.json`. Publishable to the VS Code Marketplace.

### Changed

- The out-of-the-box posture for writes is now **safe-by-default** (preview first) — see Breaking changes.

### Documentation

- **DX-3 hero demo.** A "Quick demo" section in the README and the docs site shows the three
  signature moves in one call each: find-usages (`servicenow_where_used`), what-runs-on-save
  (`servicenow_trace_table_event`) and dev-vs-prod drift (`servicenow-mcp-ai drift`). The matching
  screen-capture GIF is the only remaining DX-3 piece.
- **CLI reference.** The README now documents the `servicenow-mcp-ai` command-line surface — the
  server, `login` and `drift <a> <b>` invocations — with their parameters and exit codes.

  - `flows`: `servicenow_trace_table_event` (deterministic, ordered simulation of what a table operation runs — business rules by phase, flows, workflows, notifications — with a Mermaid flowchart), `servicenow_list_flows` / `servicenow_get_flow` (Flow Designer + legacy workflows), `servicenow_get_flow_runs` (execution evidence from `sys_flow_context`).

  - `SN_CODESEARCH=true` makes `servicenow_search_code` use the Code Search API (`sn_codesearch`) when available, with a fallback to the LIKE iteration (FT-7).
- `servicenow_compare_instances` and `servicenow_snapshot_instance` now warn (per section) when a read hit the `SN_MAX_RECORDS` cap, so a partial `sys_dictionary`/script/plugin/app read can no longer be presented as a complete diff or snapshot. Backed by a new `QueryResult.truncated` flag set when the cap is reached while `X-Total-Count` shows more rows.

### Changed

- Every ServiceNow API module now unwraps the `result` envelope through the shared `expectResult`/`expectResultArray`, so a malformed response is a uniform error instead of `undefined` data (`aggregate`, `cmdb`, `catalog`, `change`, `knowledge` joined `table`/`attachment`/`meta`/`email`).
- The Batch API now enforces the package policy axis: a sub-request to a denied package (`SN_PACKAGES_DENY`) is refused, and a write to a read-only package (`SN_PACKAGES_READONLY`) is blocked — a batch can no longer bypass the package policy that filters the normal tool list.

### Fixed

- `fetchAll` reads that stopped at the `SN_MAX_RECORDS` cap were silently treated as complete by the instance comparison/snapshot tools (under-reporting drift on large instances).

### Security

- The `.env` file is now written owner-only (`0600`) instead of the default `0644` — it holds a plaintext password.
- Without `SN_ALLOWED_HOSTS`, only `*.service-now.com` instances are contacted; a redirected or mistyped host can no longer silently receive Basic credentials. Set `SN_ALLOWED_HOSTS` to opt in a custom or sovereign-cloud domain.
- The Batch API rejects non-canonical sub-request paths (`//`, `/./`, `/../`, and their percent-encoded forms), closing a path-traversal bypass that let a batch reach a denied table or package surface that ServiceNow's dispatcher would normalize and route.
