## 0. Executive summary — what we are missing

1. **The gate is red today** _(fixed 2026-09-03 by H-1 — SDK `^1.30.0`, lock-only audit fix; kept here as the evidence the review found)_. `npm audit --omit=dev --audit-level=high` (the last step of
   `npm run check`) exits 1 on 6 advisories that all arrive through `@modelcontextprotocol/sdk`
   1.29.0; a lock-only fix exists (§5 R-set, §3 SEC-22 → H-1).
2. **Two verified safety defects in the shipped surface:** `set_credentials` can redirect stored
   secrets to any `*.service-now.com` host (SEC-01 → H-2), and an injected `apply:true` executes
   any write with no preceding plan and no human confirmation (SEC-08 → H-3). Four policy-axis
   bypasses sit next to them (batch, import set, attachments, plugin APIs → H-4).
3. **The HTTP transport is single-session and process-global:** a second client gets HTTP 400, a
   `DELETE` kills the server for everyone, and `use_instance` from one client switches the profile
   for all (T1/T2/SEC-20 → H-7).
4. **The "understands your instance" thesis has a correctness hole:** `trace_table_event` ignores
   inherited (`task`) and global business rules (G1 → S-1); script intelligence sees 9 of ~25
   script-bearing artefact families (G3 → S-4); where-used is text-only (G4 → S-9).
5. **Writes are not capturable or reversible:** no update-set awareness, no before-state in the
   journal, no revert (G7 → H-5, S-2, S-6). This is also the largest competitive gap.
6. **Protocol features the SDK already offers are unused:** `instructions`, completions,
   cancellation/progress via `extra`, `listChanged`, `outputSchema` on 65/67 tools, resource errors
   as 200 JSON (P1–P8 → M-1…M-6).
7. **Onboarding starts at the wrong place:** no `init`, no `--help`, an unconfigured server is
   invisible to the model, API-key/OAuth users read as "not configured", three hand-maintained env
   docs drift, 2 of ~10 clients documented (ON-1…ON-9 → D-1…D-4).
8. **Engineering platform is one major behind:** Node 20 (EOL) floor, zod 3, TS 5.9, ESLint 9, a
   stale coverage guard, ~10 singletons, ~20 untyped env reads, `tools/list` at ~15.6k tokens,
   versions drifting across five manifests, an unpinned extension spawn (R/A/C/H/B → E-1…E-7, D-6).
9. **Adoption is flat** (~147 downloads/week, 8 stars, 0 user issues, stale registry duplicates,
   no Open VSX) — distribution and one visible differentiator demo belong in the 3.0 gates
   (AD-1 → D-6, O-3).

What is already ahead of the field and must not regress: the full auth matrix (OAuth 2.1 + PKCE,
client credentials, JWT bearer, API key, bearer, mTLS), profiles + drift gate, plan/apply +
journal + redaction + SSRF host guard, script intelligence + Mermaid, strict schemas with
`readOnlyHint` on every read tool, stderr-only logging.

## 1. MCP protocol / SDK audit

### Baseline facts

- **SDK installed 1.29.0** (pinned by the lock); declared `^1.12.0` lets an npm consumer resolve
  any 1.x ≥ 1.12 — the code uses `registerTool` / `elicitInput`, which did not exist in 1.12
  (exact minimum UNVERIFIED; the floor is certainly too low).
- Protocol versions supported by SDK 1.29: latest `2025-11-25`; supported `2025-11-25`,
  `2025-06-18`, `2025-03-26`, `2024-11-05`, `2024-10-07`; default negotiated `2025-03-26`.
- **zod** installed 3.25.76; declared `^3.23.8` is below the SDK peer range `^3.25 || ^4.0`.
- Registration uses the modern `registerTool` / `registerResource` / `registerPrompt` APIs
  (`src/mcp/registry.ts:216`, `src/mcp/resources.ts:36`, `src/mcp/prompts.ts:12`); no deprecated
  `server.tool()`; `server.server` is reached only for elicitation/logging.
- stdio hygiene is clean: the logger writes stderr only (`src/core/logging.ts:55`);
  `process.stdout.write` appears only in the `drift`/`doctor` CLI paths that exit before the server
  starts; no `console.log` in `src/`; the launcher uses `console.error`.
- Annotations: 67/67 `readOnlyHint`, 64/67 `openWorldHint`, 22 write tools of which 21 set
  `destructiveHint`/`idempotentHint`; every tool/resource/prompt has a `title`.

## 7. Cross-cutting themes (what the five lenses agree on)

- **One source of truth is missing in four places:** settings (A4/C1/ON-5/ON-9), versions (B2/ON-8),
  counts (D1/DS-1) and tool naming (TE-3/TE-4). Every one of them is a generated artefact in 3.0
  (E-4 → D-3, H-9, M-7).
- **Session is the missing unit.** Profile, caches, log level, credentials and the journal are all
  process-scoped (T2/A3/P7/SEC-20/C-7/C-8). E-3 + H-7 introduce it once.
- **The rails are strong but have edges.** Policy axes (SEC-02…07/G16), plan/apply (SEC-08/09/P5),
  redaction (SEC-13) and the journal (SEC-11/12/G7) each have one or two paths around them. H-3…H-6
  close the edges; S-2 turns the journal into a feature.
- **The intelligence is right on the mainline and wrong on the edges** — inheritance (G1), artefact
  breadth (G3/G15), structural references (G4), flow depth (G11), ACL completeness (G6). S-1, S-4,
  S-5, S-9 and S-3 widen it without changing the approach.
- **The protocol surface is a 2025-03 server on a 2025-11 SDK** (P1–P8). M-1…M-6 are mostly
  plumbing, not design.
- **Distribution, not features, is the adoption bottleneck** (AD-1/ON-6/ON-7/ON-8/PR-2/EX-1) — hence
  D-4…D-8 and the owner gates sit inside the 3.0 exit criteria rather than after them.
